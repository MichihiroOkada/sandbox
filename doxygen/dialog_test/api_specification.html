1. 概要

本書は dialog_test のソースから確認できるクラスと関数のAPIおよび処理をまとめる。実装コメントがない関数も、コード上で確認できる動作を記載した。

このソースには、現在のVisual Studioプロジェクトでビルド対象になっている構成と、同じフォルダー内にある別のMFCダイアログアプリ構成が含まれる。プロジェクトファイル dialog_test.vcxproj が列挙しているコンパイル単位は CDialogError.cpp、Controller.cpp、main.cpp である。

2. 実行時の構成

  1. main() がMFCを初期化する。

  2. Controller::run() が CDialogError をモーダル表示する。

  3. ダイアログのOKまたはCancel操作を RESULT_OK / RESULT_CANCEL として受け取り、結果に応じたメッセージを標準出力へ出す。

3. 定数

3.1. RESULT_OK

Controller.h で定義される列挙値 100。エラーダイアログでOKボタンが押されたことを表す。

3.2. RESULT_CANCEL

Controller.h で定義される列挙値 101。エラーダイアログでCancelボタンが押されたことを表す。

4. クラスAPI

4.1. Controller

CDialogError を所有し、ダイアログ処理を開始する制御クラス。

4.1.1. 前提

このクラスはテスト実装

4.1.2. 公開メンバー

宣言 説明 処理・戻り値

Controller()

コンストラクター

メンバー m_dialogError を既定構築する。

特別な処理は行わない。メンバーは通常のC++破棄処理で破棄される。

m_dialogError.show() を呼ぶ。結果が RESULT_OK なら OK Button pushed、RESULT_CANCEL なら Cancel Button pushed を標準出力へ出す。常に 0 を返す。

4.2. CDialogError

CDialogEx を継承するモーダルダイアログ。画面サイズに合わせてウィンドウとボタンを配置し、画像を描画する。

4.2.1. 公開メンバー

宣言 説明 処理・戻り値

CDialogError(CWnd* pParent = nullptr)

コンストラクター

リソースID IDD_DIALOG_TEST_ERROR を使って基底クラスを初期化する。pParent は親ウィンドウで、省略時は nullptr。

virtual ~CDialogError()

デストラクター

追加の処理は行わない。

int show()

モーダル表示

DoModal() の結果を整数で返す。戻り値は通常、ダイアログの終了コードであり、OK / Cancel はそれぞれ RESULT_OK / RESULT_CANCEL。

BOOL OnInitDialog()

ダイアログ初期化ハンドラー

タイトルバーを隠す。対象モニター情報の取得に成功した場合、モニター領域の内側10%を起点として幅・高さ80%の位置とサイズに設定する。OK / Cancel ボタンを右下に配置し、静的テキストを OlympusLOGO に設定する。ダイアログと子コントロールにメイリオ10ポイントのフォントを設定し、GDI+を初期化する。初期化後 TRUE を返す。

4.2.2. 保護メンバー

宣言 説明 処理・戻り値

virtual void DoDataExchange(CDataExchange* pDX)

ダイアログデータ交換

CDialogEx::DoDataExchange(pDX) に委譲する。DDX/DDV用の個別バインドはない。

4.2.3. 公開メンバー（メッセージハンドラー）

宣言 説明 処理・戻り値

afx_msg void OnPaint()

描画ハンドラー

./res/olympus.png を読み込み、成功時はクライアント領域の座標 (0, 40) に 200 x 200 ピクセルで描画する。画像読み込みに失敗した場合は何も描画しない。

virtual BOOL OnDestroy()

破棄ハンドラー

基底クラスの OnDestroy() を呼び、GDI+トークンが有効ならGDI+を終了してトークンを0にする。その後 TRUE を返す。

afx_msg void OnBnClickedOriginal()

OKボタンの通知ハンドラー

EndDialog(RESULT_OK) でダイアログを閉じる。

afx_msg void OnBnClickedCancelOriginal()

Cancelボタンの通知ハンドラー

EndDialog(RESULT_CANCEL) でダイアログを閉じる。

4.2.4. 非公開メンバー

宣言 説明

ULONG_PTR m_gdiplusToken

GDI+の初期化トークン。初期値は0。

CFont m_font

ダイアログおよび子コントロールに設定するフォント。

4.2.5. リソース・実行上の前提

  • IDD_DIALOG_TEST_ERROR のダイアログリソースに、IDOK_ORIGINAL、IDCANCEL_ORIGINAL、IDC_STATIC_TEXT_ORIGINAL の各コントロールが存在すること。

  • GDI+画像 res/olympus.png は実行時のカレントディレクトリから ./res/olympus.png で参照できること。ファイルが見つからない場合、ロゴ画像は表示されない。

  • OnInitDialog() はGDI+を初期化する。初期化結果は現在の実装では検査していない。

5. エントリーポイント

5.1. int main(void)

main.cpp のアプリケーション開始関数。

  1. AfxWinInit() でMFCを初期化する。

  2. 初期化失敗時は 1 を返して終了する。

  3. 成功時は Controller を生成して run() を呼び、最後に 0 を返す。

7. ファイル構成

ファイル 役割

main.cpp

MFC初期化と Controller の起動。

Controller.h/.cpp

終了コード定義とダイアログ呼び出し制御。

CDialogError.h/.cpp

エラーダイアログ、配置、描画、終了処理。

dialog_test.h/.cpp

別構成のMFCアプリケーションクラス。現在のプロジェクトのコンパイル項目外。

dialog_testDlg.h/.cpp

別構成のメインダイアログとAboutダイアログ。現在のプロジェクトのコンパイル項目外。

resource.h、dialogtest.rc

ダイアログ、ボタン、アイコンなどのリソース定義。

framework.h、pch.h、targetver.h

MFC / Windows SDKの共通インクルードおよびプリコンパイル済みヘッダー設定。

8. 仕様上の注意

  • Controller::run() はダイアログの結果にかかわらず 0 を返す。呼び出し元では終了状態を区別できない。

  • CdialogtestApp / CdialogtestDlg と main() / Controller は別の起動構成を表している。現行プロジェクトでは前者の .cpp ファイル群がコンパイル項目に含まれていない。
